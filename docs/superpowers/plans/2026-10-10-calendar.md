# Calendar and Calendar Field Implementation Plan

> **For agentic workers:** Implement one sub-phase at a time. Each sub-phase is reviewed (Opus,
> against origin/main conventions) and committed by the user before the next starts.

**Goal:** Replace the split client/Turbo calendar with one server-rendered grid contract enhanced by
one `calendar` controller, on a date-only core, and add `sp_calendar_field` on the modal foundation.

**Design:** [Calendar and calendar field](../specs/2026-09-11-calendar-modernization-design.md)
(D1–D13). This is Phase 6 of the [combobox plan](./2026-10-05-combobox-modernization.md) and gates
its Phase 7.

## Decisions (2026-10-10)

- Six sub-phases, 6a–6f, one reviewed commit each.
- Legacy stays working until Phase 7: `calendar-{month,year,decade}`, the `*-selector` controllers,
  the `Calendar` plumber, `combobox-date`, `sp_calendar_month`, `sp_calendar_turbo*`, and
  `Calendar::Turbo::*`. New code does not depend on them.
- The new inline helper is `sp_calendar`; the field with a calendar dialog is `sp_calendar_field`.
- Shared fixtures (D8) live in `stimulus-plumbers/tests/fixtures/date/*.json`. Vitest imports them;
  Rails tests read them by relative path, as `password/parity_test.rb` reads
  `password_rules.json`. Nothing ships in either package.
- Navigation links are the current URL plus `<id>[displayed]=YYYY-MM-DD&<id>[view]=…`; the app
  reads them and re-renders the same `sp_calendar` call, so selection and constraints never
  travel in the URL and the library adds no route.
- No new `as:` value: 6e exercises `sp_calendar_field` directly and Phase 7 switches `as: :date`.
- Calendar and calendar field snapshots land in 6f, once the theme exists; the snapshot superset
  rule is checked at the end of Phase 6.

## Global constraints

- Conventions: controller helpers are `_`-prefixed; listeners share one `AbortController` per
  lifetime; `data-action` wires `onX(event)` only; Rails validates with per-component
  `validate_choice!`/`validate_id!`; ids derive from `*_id_for` class helpers.
- Test boundaries: date logic in vitest; HTML and ARIA in Rails unit tests; UX behavior and WCAG in
  Rails a11y; engine-native behavior only in `test/browser`; snapshots are a superset of a11y
  states. Tests assert goals, not the absence of legacy behavior.
- Docs follow the Doc Update Rule: one fact in one place; no test references in docs.
- Never run `test:snapshots:update`; CI regenerates baselines.
- Every sub-phase leaves vitest, Rails unit and a11y, Tailwind unit, MCP, browser, rubocop,
  eslint, and the prettier scripts green.

## Phase 6a — Date-only core (spec D2, D8)

- Create `stimulus-plumbers/src/date/index.js`: `parseDateKey`, `dateKey`, `compareDate`,
  `addDays`, `addMonths(date, n, overflow = 'clamp')`, `addYears(date, n, overflow = 'clamp')`,
  `daysInMonth`, `weekday`, `monthGrid(date, firstDayOfWeek)`, `isDisabled(date, constraints)`,
  `constraintErrors(constraints)` for D9, and `focusDate` for D4. Date keys at the boundaries,
  `{ year, month, day }` parts for arithmetic; years 0001–9999; no `Date` at all.
- Create fixtures `tests/fixtures/date/{arithmetic,grid,constraints}.json`: month lengths and leap
  years, January 29–31 and February 29 stepping, century rules, every `firstDayOfWeek`, range and
  disabled sets, invalid and partial keys.
- Also `focus.json` (D4 precedence) and adjacent-month visibility cases, and invalid-constraint
  cases in `constraints.json`, used by 6b and 6c.
- Tests: `tests/unit/date/*.test.js` runs the fixtures inside `describe.each(ZONES)` (`UTC`,
  `Asia/Singapore`, `America/Los_Angeles`, `Australia/Lord_Howe`) that sets `process.env.TZ` in
  `beforeAll` and restores it in `afterAll`; it runs in the normal `npm test`, so CI is unchanged.
- `plumbers/plumber/date.js` stays for instant parsing (`content_loader` uses it); `src/date/` never
  imports it.
- Internal only: not exported from `src/index.js` until a consumer needs it.

## Phase 6b — Rails renderer (D3, D4, D7, D9, D12)

- `sp_calendar(id:, displayed:, selected:, today:, view:, navigation:, selectable:,
  show_other_months:, min:, max:, disabled_dates:, disabled_weekdays:, disabled_months:,
  disabled_years:, first_day_of_week:)`.
- Components: `Calendar#render` (status region, frame) with `STIMULUS_CONTROLLER = "calendar"`;
  `Calendar::Header` (previous/next, heading, zoom out); views `Calendar::{MonthView,YearView,
  DecadeView}` on a `Calendar::View` base; `Calendar::Period` (what is shown, plus the link
  builder); and `Calendar::Constraints` (D9 normalization; the `constraints.json` invalid cases
  raise `ArgumentError`). Year and decade cells are zoom-in links. The legacy `Calendar#month`,
  `#year`, and `#decade` stay until Phase 7.
- The heading that labels the grid sits inside the frame; a persistent visually hidden
  `role="status"` outside the frame announces period changes (6d fills it).
- Previous/next links use the URL rule in Decisions; they work without JavaScript. `displayed:` and
  `view:` fall back on invalid URL values; links stop at the years 0001–9999.
- The root carries settings as `data-calendar-*-value`s (selected, selectable, navigation,
  constraints); the grid carries `data-displayed` and `data-view` for 6d. Week layout is the
  server's, so the controller reads rows rather than a first-day value.
- Each day button carries `data-display` with Rails' localized date (`l(date)`), so JS never
  formats dates.
- Markup per D3: `table[role=grid]` labelled by the live heading; `th[scope=col][abbr]`;
  `td[role=gridcell][aria-selected]` around `button[data-date][aria-label]`; `aria-current="date"`
  for today; exactly one enabled button with `tabindex="0"` chosen by D4.
- `first_day_of_week` resolves from the option or locale once and is emitted as an integer.
- New theme keys for the table contract, with placeholder Tailwind resolvers so `resolve` never
  warns; styled in 6f. The old `calendar_*` keys stay for legacy until Phase 7.
- Tests: Rails unit tests for markup, ids, D4 precedence, and constraints;
  `test/stimulus_plumbers/components/calendar/parity_test.rb` runs the 6a fixtures through
  `Calendar::Constraints` and the views; a11y scans of month/year/decade in the new sandbox route
  `/components/calendar/inline` (`accessibility/components/calendar/inline_accessibility_test.rb`).
- Docs: Rails `calendar.md` (`sp_calendar` section), README Components row, theme keys,
  ARIA.md calendar section.

## Phase 6c — `calendar` controller and keyboard (D4, D5, D10)

- `calendar_controller.js` enhances server markup: normalizes to one Tab stop (warns on malformed
  markup), keeps focus separate from selection, commits on Enter/Space or click.
- D5 keys on day buttons: Arrows, Home/End (week), Page Up/Down (month, clamp), Shift+Page
  Up/Down (year, clamp). Year and decade views use the same roving focus with their column
  geometry.
- Malformed manually authored markup reports a clear `console.error`: constraints through
  `constraintErrors`, and missing date keys, per D9.
- Selection per D10: `calendar:before-change` (cancellable) then `calendar:change`, detail
  `{ value, previousValue }` as date keys; form reset restores the initial value.
- Leaving the rendered period records the intended date and dispatches `calendar:before-navigate`
  (cancellable) and `calendar:navigate`; 6d owns the replacement and `calendar:navigated`.
- Tests: vitest for keyboard and selection logic; Rails a11y for the keyboard contract and
  selection.
- Docs: JS `calendar.md` (`calendar` section), README Controllers table and export.

## Phase 6d — Navigation and focus intent (D6, D7)

- `calendar:navigated` with `{ from, to, focusDate, view }`; year/decade activation zooms in
  through the same navigation.
- `navigation: :turbo`: previous/next and keyboard moves load the frame from the Decisions URL.
  On `turbo:frame-load` the controller
  verifies the period, restores the recorded focus date (clamped to the nearest enabled date),
  re-establishes one Tab stop, focuses only after a keyboard-originated move, writes the new
  heading to the status region, and dispatches `navigated`. Pointer navigation keeps focus on the
  navigation control.
- `navigation: :events`: the controller dispatches only; framework-neutral consumers replace the
  grid with conforming markup.
- A Turbo cache restore builds a new instance from the reflected `selected` value, so form reset
  after back navigation restores the user's choice; kept, as combobox does. `turbo:before-cache`
  clears the pending navigation and the status text.
- Tests: vitest for intent resolution, stale responses, reconnect, and Turbo cache cleanup; Rails
  a11y for keyboard month-to-month navigation and the announced heading. Loading and failed
  responses get snapshot cases with `page.route` in 6f, as in Phase 4b.

## Phase 6e — `sp_calendar_field` (D1, D11, D13)

- `sp_calendar_field(form:, attribute:, label:, …constraints)`: a read-only display, the format
  hint, the hidden canonical input, and an `sp_modal` whose trigger slot is the "Choose date" button
  and whose body holds `sp_calendar` plus a Cancel button.
- Wiring, no outlets: the calendar-field root takes `modal:opened->calendar-field#onOpened`, which
  focuses the grid's one Tab stop (Rails chose it per D4; no `autofocus`, which Turbo re-applies on
  every frame render), and `calendar:change->calendar-field#onChange`, which copies the value into
  the hidden input and the activated day's `data-display` into the display, then completes the
  dialog with a native `close(value)`, which the Dialog plumber reports as `modal:closed`.
  Cancel and Escape change nothing.
- `calendar_field_controller.js` owns only field state; it does not duplicate the modal lifecycle or
  focus handling.
- Tests: Rails unit tests for markup and a validation re-render with a submitted value; Rails a11y
  for open, select, cancel, Escape, and focus restore; browser for initial focus inside the
  dialog (dialog focusing differs by engine). New sandbox route `/components/calendar/field`.
- Docs: Rails `calendar_field.md` (new), README rows, ARIA.md calendar field section, and a D13
  line: native `date_field` is the default, including Hotwire Native.

## Phase 6f — Tailwind theme and browser gates

- Theme keys from 6b and 6e: table, headers, cells; day default, hover, focus, today, selected,
  disabled, and outside states, distinct without color alone; heading and navigation; year and
  decade geometry; calendar field and dialog layout; frame busy state.
- Snapshots: every calendar and calendar field a11y state from 6b–6e, loading and failed
  navigation, forced colors (Chromium), long localized labels.
- Browser: 400% zoom, touch viewport, reduced motion, and native `date_field` on desktop and mobile
  projects. WebKit does not focus a clicked
  link, so pointer previous/next leaves focus on `body` there; record the engine difference.
- Manual AT gates (VoiceOver, NVDA, iOS, Hotwire Native) are Phase 8 of the combobox plan.
- Deferred: long localized label snapshots (the sandbox has no non-en locale); reduced motion (the
  calendar has no animation).

## Phase 7 hand-off

Phase 7 of the combobox plan replaces `sp_calendar_field` with `sp_combobox_date` on a popover
(decisions 2026-10-11), switches `as: :date`/`as: :time` to the date/time comboboxes, and deletes
the legacy calendar controllers, selectors, plumber, `sp_calendar_month`, `sp_calendar_turbo*`,
`Calendar::Turbo::*`, legacy `Calendar#month/year/decade`, and the old `calendar_*` theme keys
except `calendar`, which the `sp_calendar` root also uses.
